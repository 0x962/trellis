THE WORKFLOW GUIDE

One task.
From plan to review.

Trellis keeps the task, the agent’s session, and the resulting diff connected. Here is how those pieces fit together.

These commands require an installed Trellis CLI connected to your Trellis instance. Replace the fictional project, ticket, and repository values with your own. Use trellis --help to inspect available commands.
01

Read the project.

A project holds repositories, tickets, notes, and its workflow statuses. Read its configured statuses before you move a ticket.

trellis project list
trellis project show ACM
trellis project status list ACM
02

Make the task concrete.

Put the intended result, file ownership, and verification steps in the ticket. Group the ticket into an epic and a wave. Add dependencies when it needs another ticket’s result.

Set the contract on an existing ticket. This command changes the ticket.

trellis ticket contract set ACM-12 \
--result "Save a valid email address." \
--file account/email.ts \
--file account/email.test.ts \
--verify "npm run test:account"

Then read the saved contract and dependencies.

trellis ticket contract show ACM-12
trellis ticket dependency list ACM-12

03

Assign an agent.

Check the current assignment before you start another agent. An assignment identifies the task. Its session holds the conversation and workspace.

trellis agent list --ticket ACM-12

To start a new assignment, use trellis agent start --ticket ACM-12. This command starts an agent; the website example does not.

You can send instructions, pause work, and resume the same session. A stopped agent keeps its conversation and workspace.

04

Connect the result.

Trellis represents a GitHub pull request as a diff. Link the diff to its ticket. Give the reviewer an explanation and evidence of the tests.

Link an existing pull request. This command changes its relationship in Trellis.

trellis diff link https://github.com/acme/app/pull/42 \
--ticket ACM-12

Inspect the linked diff and its saved evidence.

trellis diff show acme/app#42
trellis diff evidence show acme/app#42

The GitHub pull request, the ticket status, and the local request for review have separate states.

05

Inspect the review gaps.

A review flow gives agents defined responsibilities and records their findings. Read those findings and the remaining checks before you decide what ships.

trellis diff comment list acme/app#42
trellis diff check acme/app#42

The check reports review gaps without a state change. A successful run does not mean that every finding is resolved.
